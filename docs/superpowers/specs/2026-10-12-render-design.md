# 確認用の画像（render）設計

- 日付: 2026-10-12
- ステータス: 設計済み
- 対象: M3-4（開発体験: ビューアなしで複数方向の画像を出し、エージェントが設計ループで見る）

## 背景

`validate --json`（M3-3）で、配置の矛盾・重なり・穴の衝突・外形はエージェントが読めるようになった。捕まえられないのは、
組み立てとしては正しいが意図と違う設計だ（天板の向きが逆、棚の高さが違う、脚の向きが違う、など）。全体を見れば気づける。

今ある `drawing` は build123d で正確に描くが、確認には向かない。2 段の棚の例を PNG にすると次のとおり。

- A3 の枠と表題欄のせいで各方向が小さい（正面・側面は 200px ほど）。
- 部材に名前がなく、どの線がどの部材か分からない。
- 隠れ線とダボ穴が重なり、立体図が込み入る。

## 目的

エージェント（と人）が 1 枚の画像で設計の全体を見て、依頼と違うところに気づけるようにする。ビューア（ocp_vscode）はいらない。

## 合意した方針（決定事項と理由）

1. **形状は build123d で正確に描く。** 部材を箱で描く軽い方法より、穴の位置や角の丸めまで実形状どおりであることを
   重視する（ユーザーの判断）。
2. **確認用の 1 枚にする。** 枠と表題欄をなくし、正面・右側面・上面・立体の 4 方向を 2×2 に大きく並べる。部材 ID の
   ラベルを付け、隠れ線は描かない。エージェントは 1 回読めば全体が分かる。
3. **新しいコマンド `render` にする（`drawing` に PNG の出力を足さない）。** 図面は印刷する書類、確認用の画像は見るための
   もので、オプション（用紙・表題と、画像の大きさ）が違う。投影のコードは共有する。

## スコープ外

- 影付き（陰影）の描画（OpenGL などが要る）
- 問題のある部材の色分け（問題は `validate --json` で分かる）
- 方向ごとに別の画像を出すこと
- 「意図どおりか」を自動で判定する評価（M5 の回帰テスト）

## 設計

### 1. 画像とコマンド

```bash
nichiyou-daiku render design.nd                    # → design.png
nichiyou-daiku render design.nd -o check.png --size 1400 --fillet-radius 5
```

- 正方形の PNG 1 枚。既定は 1 辺 1400px（Claude が縮小せずに読める大きさ）。`--size` で変えられる。
- 正面（-y から）・右側面（+x から）・上面（+z から）・立体（(1, 1, 1) の方向から）を 2×2 に、同じ縮尺でできるだけ
  大きく並べる。方向の定義は `drawing` と同じ。軸は `validate --json` の `size_reference`（最初に宣言した部材）の軸で、
  JSON の座標とそろう。
- 形状は `drawing`・`export` と同じく build123d で作る（下穴、`--fillet-radius` の角の丸め、既定 5mm）。見える線だけを描く。
- 各方向に見出しを付ける（`front (from -y)`、`right (from +x)`、`top (from +z)`、`isometric`）。
- 各部材の ID を、その方向での部材の中心に書く。部材の中心から視点への直線が他の部材の箱を通るときは、その方向では
  書かない（上の天板に隠れる下の棚板には、上面図でラベルが付かない）。名前が別の部材の上に載らないようにするため。
- 隅にファイル名と外形を書く（例: `two-tier-shelf.nd  600 x 300 x 800 mm`）。部材がつながっていなければ外形の代わりに
  `pieces not connected` と書く。
- 問題があれば、他のコマンドと同じく警告して描く。
- 標準入力から読むときは `-o` が必須。出力が入力ファイルを上書きするときは止める（どちらも `drawing` と同じ）。
- build123d（viz の extra）が必要。

### 2. コードの置き場所

- **新規 `shell/views.py`（build123d に依存しない）**
  - 4 方向の定義（視点・上方向・見出し・2×2 の位置）。`drawing.py` の `_VIEWS` をここへ移し、`drawing` と `render` で
    共有する。図面の出力は変えない。
  - ラベルの計算: 方向ごとに、隠れていない部材の ID と、その中心の 3D の位置を返す。隠れの判定は、中心から視点の方向への
    半直線と、他の部材の箱（配置の `Pose.bounds`）との交差で行う。
- **新規 `shell/render.py`（build123d が必要。`shell/__init__` からは import しない）**
  - 4 方向を見える線だけで投影し、正方形に 2×2 で並べる。
  - ラベルの 3D の位置は、線と同じ正射影で画像の座標に写す。
  - SVG に見出し・ラベル・注記を `<text>` で書き足し、cairosvg で PNG にする。SVG も返す（テストで中身を確かめるため）。
- **新規 `cli/commands/render.py`** と `cli/dsl_cli.py` への登録。読み込み・組み立て・build123d への変換・警告は、既存の
  `cli/utils.py` の関数を使う。
- **`bin/nichiyou-daiku`**: `render` も viz の環境で動かす（`export`・`drawing`・`view` と同じ扱い）。

### 3. スキルとドキュメント

- `skills/design/SKILL.md`: 手順 5（外形の確認）の後に「6. 見て確かめる」を足し、以降の番号をずらす。
  - `nichiyou-daiku render <name>.nd -o <name>.png` を実行し、PNG を読む。
  - 依頼と比べる: 板の向き、棚や幕板の高さ、脚の向き、浮いている部材がないか。違えば直して手順 4 に戻る。
  - 初回は build123d を入れるので数分かかる。
- `docs/dsl-specification.md` の CLI の節に `### Check Image (requires build123d)` を足す。README のコマンド例に 1 行足す。

### 4. テスト

- `shell/views.py`（build123d 不要）
  - 2 段の棚の例で、上面図には下の棚板のラベルがなく、正面図にはある。
  - ラベルの位置は、その部材の箱を各方向に投影した範囲の中にある。
  - 4 方向の見出し。
- `shell/render.py`
  - PNG の大きさが `--size` どおりで、白紙ではない。
  - SVG に各部材の ID（隠れていない方向の数だけ）、4 つの見出し、外形の注記がある。
  - `drawing` の図面が変わらない（既存の図面の回帰テスト）。
- CLI: 既定の出力名、`-o`、`--size`、問題があると警告して描く、標準入力で `-o` がないと止まる、入力を上書きしない。
- ラッパー: `render` に viz の extra が付く（`tests/test_plugin.py`）。
- ドキュメント: リンクとパスのテスト。
