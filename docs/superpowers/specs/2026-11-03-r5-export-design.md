# R5 3D の書き出し（STL と STEP） 設計

- 日付: 2026-11-03
- ステータス: 設計（未実装）
- ブランチ: `next`（作業は `next-r5-export`）
- 親: `2026-10-29-next-generation-rust-core-design.md`（R5）、`2026-11-02-countersinks-and-part-titles-design.md`（皿取り）

## 目的

Rust 版の CLI に `export` を作る。家具の 3D の形を STL（三角形の網）と STEP（正確な面の立体）で書き出す。
使い道はユーザーによると、ほかの 3D ビューアーで見る・共有する（STL）と、ほかの CAD で開いて直す（STEP）。

## 決定と理由

1. **角は丸めない**（ユーザー）。図面・確認用の絵・ビューアーと同じ角の立った箱にする。形が単純になり、STEP でも
   穴を確実に正しく書ける。Python 版のように長い 4 辺を丸める案は、1x4 の細い面（19mm）の座掘りが丸めた部分に
   かかり、その形を自前で組むのが難しく作り込みが大きく増えるので選ばなかった。`--fillet-radius` は受け付けるが
   使わない（`render`・`steps`・`drawing` と同じ）。
2. **穴は全部開ける**（ユーザー）。下穴・ダボ穴・座掘り・皿取りを形にする。CAD で開いたとき穴の位置と大きさを
   測れ、部品図と同じものを 3D で確かめられる。
3. **形は自前で組む**（ユーザー）。部材は「箱と、面に垂直な穴」だけなので、その形を直接組んで STEP と STL の両方に
   書く。依存は増えず、形が必ず閉じる。汎用の 3D ライブラリ（truck）の立体の演算は、依存と実行ファイルが大きく、
   演算が失敗することがあり STEP の出来も確かめが要るので選ばなかった。STL だけ先に作る案は、CAD で直す使い道に
   届かないので選ばなかった。
4. **同じ軸の線の上の穴は 1 つの段付きの穴にまとめる**。座掘りとその下穴は、片方の面からの座掘りと反対の面からの
   貫通の下穴として記録され、同じ軸で重なる（コーパスによく出る）。まとめずに円柱を重ねると面が交わり、立体が
   壊れる。
5. **別の軸の穴が食い込むときは、後の穴をその部材の形から省いて知らせる**。core のぶつかりの判定（`bores_meet`、
   ねじの太さで見る）で交わる穴は `validate` が問題として報告しているので、直し方はそちらにある。1 点でかするだけ
   の穴（コーパスに多い、ダボ穴どうしの角）は省かない。コーパスで穴の口が面からはみ出す例は 0（約 2 万 7 千の穴）。
6. **新しいクレート `nichiyou-daiku-export` に置き、core だけに頼る**。ほかの依存を足さないので、後でビューアー
   （WASM）から書き出すこともできる（R5 では作らない）。CLI はこれを呼んでファイルに書くだけ。

## 形

- 部材: 角の立った箱（幅 × 厚み × 長さ、`Piece::shape`）を組み立ての位置（`placement.pose`）に置く。単位 mm。
- 穴（`parts::piece_holes` の部材の座標の穴）: 軸の線（穴の向きの軸と、残る 2 つの座標）ごとにまとめ、軸に沿った
  半径の段の並び（回転体の輪郭）にする。
  - 皿取り（`countersink`）: 口の径から下穴の径までの円すい（90°、深さは (口 − 下穴) ÷ 2）。
  - 座掘り: 太い円柱の後、段（平らな輪）で下穴の径に移る。
  - 下穴・ダボ穴: 円柱。止まり穴（`depth` あり）は平らな底。貫通（`depth` なし）は反対の面に口を開ける。
  - 同じ軸の線の上で、離れている区間は別の穴。重なる区間は太いほうの半径を取る。
- 食い込む穴（決定 5）: 部材ごとに穴を記録の順に入れ、すでに入れた穴と交わる穴（軸の線が違うもの）を省く。
  交わりは core の `bores_meet` と同じ判定を、実際の穴の半径で行う。
- B-rep: 面は平面（箱の 6 面、段の輪、止まり穴の底）、円柱面、円すい面。辺は直線と円（円柱・円すいの面は 1 本の
  継ぎ目の線を持つ）。面の向きは立体の外向き。
- STL: 同じ形を三角形にする。円の分割数は、弦のずれが 0.05mm 以内になる数（最低 16）。穴の口がある平面は、口の
  多角形を穴として三角形に分ける。全部材を 1 つのバイナリ STL にする。
- STEP（ISO 10303-21、AP214）: 部材ごとに 1 つの `MANIFOLD_SOLID_BREP`、名前は部材名。全部材を 1 つの形の表現に
  並べる（色・組み立ての階層は付けない）。頭書きに題名（入力のファイル名）、書いた日時、
  `nichiyou-daiku <版>`。長さの単位は mm。

## CLI

- `export FILE [-o PATH] [-f stl|step|stp] [--fillet-radius R]`。出力先と形式の決め方は Python 版
  （`resolve_export_target`）と同じ:
  - `-f` だけ: `<入力>.<-f の値>`（`stp` なら `.stp`、形式は STEP）。`-o` だけ: 拡張子（`.stl`・`.step`・`.stp`、
    大文字小文字を問わない）から形式を決める。
  - どちらも無い: `Error: Either output file (-o) or format (-f) must be specified.`
  - 知らない拡張子: `Error: Cannot detect format from extension '<拡張子>'. Please specify format with -f option.`
  - 食い違う: `Error: Output extension '<拡張子>' does not match format '<-f の値>'.`
  - 標準入力 `-` のときは `-o` が要り、入力のファイルは上書きしない（ほかのコマンドと同じ文）。
- メッセージ: 組み立ての問題は `Warning: …`。省いた穴は
  `Warning: <部材>: the φ<径> hole at <面> (<位置>) runs into another hole; it is left out of the 3D. Fix the collision validate reports`。
  成功は `Successfully exported to: PATH`。書けないときは `Error exporting file: cannot write PATH: …`。

## テスト

- 形の決まりごと（Rust の単体テスト、コーパスの組み立てられる全件）: STL の網が閉じている（どの辺もちょうど 2 枚の
  三角形が逆向きに共有する）、体積が正。B-rep がオイラー・ポアンカレの式（V − E + F − (L − F) = 2(S − G)）を満たす。
  B-rep の体積が箱 − 穴の計算どおり、STL の体積が円の分割の誤差の範囲で合う。
- Python 版との突き合わせ: 例と文書の例について、Python 版（build123d、`fillet_radius=0`）の部材ごとの体積と外形を
  `tools/make_goldens.py --cli` で `NAME.solids.json` に書き、Rust の形の体積を、穴を Python の形に戻して（皿取りを
  除いて）比べる。
- STEP の読み直し: `tools/check_step.py` が Rust の STEP を build123d（OpenCASCADE）で読み、部材の数だけ正しい
  （`is_valid`）立体があること、名前、体積を確かめる。CI の Rust の環境には build123d が無いので、実装中と最終確認で
  手で走らせる。
- CLI: 出力先の決め方と 3 つのエラー文、標準入力の `-o`、入力を上書きしない、書けないときにファイルの場所、STL が
  バイナリで三角形の数が合う、STEP が `ISO-10303-21;` で始まり部材名の立体を含む、省いた穴の警告。
- 見た目: ファイルワゴンの STEP をユーザーが手元の CAD（Fusion・FreeCAD など）で開いて確かめる（部材名・穴・
  皿取り・座掘り）。

## R5 で作らないもの

角の丸め、ビューアーからの書き出し、STEP の色や組み立ての階層、ほかの形式（OBJ・3MF など）。

## R5 が終わる条件

- 上のテストがすべて通り、`make check` と `make ci-local` が通る。
- `tools/check_step.py` が例のすべてで通る。
- ユーザーが STEP を開いて確かめた。
