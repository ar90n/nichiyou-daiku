# R3b 手順の寸法（ビューアー） 設計

- 日付: 2026-10-31
- ステータス: 設計（未実装）
- ブランチ: `next`（作業は `next-r3b-dimensions`）
- 親: `2026-10-29-next-generation-rust-core-design.md`（R3 組み立てマニュアルの B）、
  `2026-10-31-r3a-assembly-steps-design.md`（A 手順送り）

## 目的

手順送り（R3a）の 3D に、その手順で足す部材をどこに付けるかの寸法線と数値を出す。CLI の `steps` の手順の
画像の右半分（寸法図）と同じ数値を、ビューアーの中で読めるようにする。

## 決定と理由

1. **寸法線と数値は 3D の中に引き、部材と一緒に回る**（ユーザー）。「Dimensions」ボタンで、その手順の
   寸法図の向き（CLI の寸法図と同じ向き）にカメラを合わせる。3D の横に平らな寸法図を並べる案は、画面が
   2 つに分かれてスマホで小さくなるので選ばなかった。
2. **寸法を出すのは CLI と同じ 2 軸**（ユーザー）。手順の寸法図の向き（R3a の `view`）から見て読める 2 本。
   3 軸すべてに引く案は、線が増えて重なりやすく、どの向きからも 1 本は潰れて見えるので選ばなかった。
3. **区切りは CLI と同じ**。その手順で足す部材と、それがつながる相手の部材の両端で止め、その外に、できた
   部分の全体の寸法を引く。0.05mm より近い止める位置はまとめる。CLI の手順の画像と数値をそろえる。
4. **区切りは Rust の core で計算し、3D のどこに置くかは web で決める**（ユーザー承認）。区切りは C（紙の
   マニュアル）と後の CLI でも使い、Python 版の正解ファイルと突き合わせられる。置き場所は見せ方なので、
   web で変えやすくしておく。置き場所まで core で計算する案は、見せ方を変えるたびに core を直すことになり、
   比べる相手もないので選ばなかった。区切りを TypeScript で計算する案は、C と CLI のために同じ処理を二度
   書くので選ばなかった。
5. **線は寸法図の向きに面した側の高さに置き、CLI の図と同じ側（below なら図の下、left なら図の左）の外に
   出す**。部材の陰に隠れず、Dimensions の向きから見ると CLI の寸法図と同じ並びになる。
6. **数値の重なりは描くたびに画面の上で調べ、lumber（材の幅か厚さと同じ区間）、普通の順に隠す。全体の寸法は
   隠さない**。CLI の「lumber は収まるところにだけ書く」を、回す・寄るたびに変わる 3D の画面でその都度
   行う形。寄れば隠れていた数値が出る。
7. **止める位置には斜めの短い線（建築の図面の印）を付ける**。3D で斜めから見ると矢印の向きが分かりにくい。
8. **Steps タブの手順 1 以降だけで出す**。部品表（手順 0）と Model タブでは出さない（Model タブの寸法は
   この先の課題）。

## 組み立て

### core（`crates/nichiyou-daiku-core`）

- `dimensioning.rs`: `shell/dimensioning.py` のうち、手順の寸法に要る分を移す。
  - `PRECISION_MM = 0.05`、`Segment { start, end, lumber }`、`Chain { axis, side, stops, segments }`、
    `Side`（`left`・`below`）。
  - `chain_for(axis, side, bounds, model, chosen) -> Chain`: `bounds` の箱の全体を両端に、`chosen` の部材の
    両端で止める。区間の両端が `chosen` のある部材の両端と一致し、長さがその部材の幅か厚さと一致すれば
    lumber。止める位置が両端だけなら `segments` は空。
  - 手順の寸法: CLI の手順の画像（`shell/instructions.py: _dimension_view`）と同じく、寸法図の向き
    （`views.axis_view(axis, side)`、上は z、z から見るときは -y）以外の 2 軸を小さい順に、その軸の単位
    ベクトルを向きに投影して横に寝れば `below`、立てば `left`。箱は `shown` の部材の世界の箱、止めるのは
    その手順の `pieces` と、その手順の接続の相手の部材（名前の順）。
  - 図面全体の寸法（`chains`）、穴の位置の寸法（`chain_from_stops`）、数値の並べ方（`spread`）は C で移す。
- view の JSON: `steps[i]` に `dimensions` を足す。座標は view のほかの値と同じく、モデルの最小の角を
  原点にし、round_mm で丸める。

  ```json
  "dimensions": [
    {"axis": "x", "side": "below", "stops": [0.0, 200.0, 219.0, 530.0],
     "segments": [{"start": 0.0, "end": 200.0, "lumber": false},
                  {"start": 200.0, "end": 219.0, "lumber": true},
                  {"start": 219.0, "end": 530.0, "lumber": false}]}
  ]
  ```

  全体の寸法は `stops` の最初と最後。

### 正解ファイル

`tools/make_goldens.py` の `steps_report` で、手順ごとに Python 版の `chain_for` の結果（上と同じ選び方、
原点をずらして round_mm）を `dimensions` として足し、`--steps-only` で作り直す。Rust のテストは R3a の
まま、view の `steps` 全体を突き合わせる。

### web

- `dimensions.ts`（WebGL に触れない）: 手順の `dimensions`、`shown` の範囲、寸法図の向きから、3D に置く
  ものを決める。
  - 見る側の面: 向きの軸の座標を、向きが正なら範囲の最大、負なら最小にする。
  - 外への向き: 寸法図の画面の上（z、z から見るときは -y）と右（上 × 見る側）を求め、below は画面の下、
    left は画面の左になる側へ、3 つ目の軸に沿って範囲の外に出す。
  - 段: 区間の段と全体の段。間隔は `shown` の範囲の一番長い辺の 8%、ただし 20mm 以上。区間が無ければ
    全体の段だけ。
  - 補助線: 止める位置ごとに範囲の縁から段まで。両端は全体の段まで、途中は区間の段まで。
  - 印: 止める位置ごとに、段の線に 45° の短い線。
  - 数値: 区間の真ん中で、段の少し外。文字は CLI と同じ形（`format_mm` に当たるもの: 小数 1 桁、`.0` は
    付けない）。種類は `overall`・`normal`・`lumber`。
- 重なりの隠し方（純粋な関数）: 画面の上の四角と順番（全体 → 普通 → lumber）を渡すと、先に見せたものと
  重なるものを隠した結果を返す。
- `viewer`: 寸法を描く・消す（線は `LineSegments`、数値は部材名と同じ HTML のラベル）。描くたびに数値の
  四角を測り、重なりの隠し方に渡す。寸法図の向きにカメラを合わせる（寄り方はその手順の部分に合わせる）。
- 画面: 視点のボタンの並びに「Dimensions」（向きを合わせる）と、入り切りのチェック（初めは入）。Steps
  タブの手順 1 以降だけで見せる。

## テスト

- Rust:
  - 正解ファイル: 組み立てられるすべての件で、手順の `dimensions` を含む `steps` が Python 版と一致すること。
  - 単体テスト: `chain_for`（0.05mm より近い位置をまとめる、lumber は部材の両端と一致し幅か厚さと同じ
    長さのときだけ、両端だけなら区間なし）、左か下かの選び方（正面・上・横の向き）。
- TypeScript（vitest）:
  - `dimensions.ts`: 正面と上から見る手順で、段が見る側の面にあること、below と left の外への出し方、
    段の間隔（8%、20mm 以上）、補助線の長さ、数値の位置と種類と文字。
  - 重なりの隠し方: 重なるものを順番に隠すこと。
  - viewer: 寸法を描く・消すと線とラベルの数が変わること（描いた部材を数える偽のレンダラーで）。
    Dimensions の向きにカメラが向くこと。
- 見た目: Tailscale 経由で PC とスマホから、ファイルワゴンの手順を送ってユーザーが確かめる。

## B で作らないもの

図面全体の寸法、穴の位置の寸法、数値の並べ方（`spread`）、印刷（C）、Model タブの寸法、寸法を自分で
足したり動かしたりすること。

## B が終わる条件

- 上のテストがすべて通り、`make check` と `make ci-local` が通る。
- WASM の大きさを測り直してこの文書に書いてある。
- ユーザーが PC とスマホで確かめた。

WASM は R3b で 0.63 MB（630,896 バイト）、gzip で 0.16 MB（160,393 バイト）。R3a の 0.59 MB／0.15 MB から、寸法の区切りの分が増えた（2026-10-31）。
