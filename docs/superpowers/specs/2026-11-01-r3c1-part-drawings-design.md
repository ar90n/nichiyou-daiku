## 目的

ビューアーで、穴のある部品の部品図（CLI の `steps` が書く `part-NN.png` と同じ中身）を見られるようにする。
図面の描き方（平行投影、隠れ線、寸法線、SVG）を Rust に移し、後の CLI でも使える土台にする。

## C の分け方（ユーザー承認）

C 紙のマニュアルは独立した大きさが 3 つ重なるので、分けて順に作る。

- **C1 部品図（この文書）**: 部材 1 本の図面。図面の土台を作る。隠れ線は 1 本の材の中だけ。
- **C2 手順の図**: CLI と同じ手順の図（斜めの図＋寸法図）。箱どうしが隠し合う隠れ線、部材名が見えるかの判定、
  向きの矢印。
- **C3 マニュアル**: 部品表・部品図・手順を 1 つのページに並べ、A4 で印刷できるようにする。

C1 は箱が 1 本なので隠れ線が簡単で、土台をそこで固められる。C2 はそれに箱どうしの隠し合いを足し、C3 は
できた図を並べる。

## 決定と理由

1. **部品図は、右の 3D の場所に入れ替えて出す**（ユーザー）。横に長い図も広い場所で読め、スマホでも上半分が
   図になる。部品表の下に小さく出す案は、欄が狭くて読めないので選ばなかった。別のページで開く案は、
   ビューアーと行き来することになるので選ばなかった（印刷は C3）。
2. **中身は CLI の部品図と同じ**: 題名、斜めの図（隠れ線、穴のある面の記号と引き出し線、基準の端の ▲）、
   穴のある面ごとの図（基準の端から測った穴の位置の寸法、全体の長さ、入らない数値は外の列と引き出し線、
   面の記号と隣の面の記号、▲）。CLI で決めた見せ方（M4-5）をそのまま使う。
3. **描き方は新しいクレート `nichiyou-daiku-drawing` に置き、SVG を返す。計算（面の記号、穴の位置、寸法の
   区切り）は core に置く**（ユーザー承認）。後の CLI（R4 の `drawing`・`steps`）もこのクレートを使う。
   図を部品（線・円・文字）の JSON で返して TypeScript で SVG にする案は、層が一つ増え、CLI には別に SVG の
   書き出しが要るので選ばなかった。TypeScript に移す案は CLI で使えないので選ばなかった。
4. **WASM の関数を別にする**（`part_drawing(source, part)`）。部品図は大きいので view の JSON に入れず、
   開いたときだけ作る。
5. **数値は Python 版の正解ファイルと突き合わせ、線の一本一本は合わせない**。題名・面の記号・穴の位置の
   区切りは一致させる。線の分け方は OCP の都合で決まっており、文字の位置は字体で変わるので比べない
   （「完全な互換性は不要」の方針）。
6. **文字は SVG の `<text>`（DejaVu Sans など）で書き、字幅は Rust に持つ表で測る**。数値が区間に入るか、
   題名を何行にするかを Rust で決めるため。その字体が無いブラウザでは少しずれるが読める。字の形を線に
   して埋め込む案は、字体のデータが大きくなるので選ばなかった。
7. **隠れ線は 1 本の材の中だけ**。箱の辺は、両側の面が裏を向いていれば隠れ線。穴は、入口の円がある面が
   表を向いていれば見え、底の円と側面の輪郭線は材の中なので隠れ線。貫通穴の出口の円は、その面の向きで
   決める。部材が 1 本なので、ほかに隠すものはない。
8. **穴のない部品には図を作らない**。CLI と同じく、切るだけの部品は部品表で足りる。

## 組み立て

### core（`crates/nichiyou-daiku-core`）

- `parts.rs` に、`core/assembly/parts.py` の部品図の面の扱いを足す。
  - `face_frame(face) -> (right, up)`（外から見た面の右と上。長い面は長さが右、上の木口は幅が右、下の
    木口は幅が左）、`face_size(face, size)`、`face_point(face, point, size)`（外から見た面の左下からの位置）。
  - `edge_neighbours(face)`（上・下・左・右の辺の向こうの面）。
  - `face_letters(holes, size)`（穴のある面に FACE_ORDER の順で A、B…。両端だけに穴があり、長い面に穴が
    無く、どちらの端も長さの軸まわりに回して同じにならないときは front にも付ける）。
  - `view_direction(faces)`（斜めの 8 方向のうち、記号の付いた面がいちばん多く見えるもの。同点は
    VIEW_ORDER の順）。
  - `part_title(model, group)`（`部材, … ×n   材種   長さ   φd ↧深さ ×n …`。穴は径の順、同じ径なら止め穴が先）。
- `dimensioning.rs` に `chain_from_stops`（止める位置から区切る。区間は lumber にしない）と `spread`（はみ出す
  数値の並べ方）を足す。

### 正解ファイル

`tools/make_goldens.py` に、組み立てられる場合に、穴のある部品ごとに Python 版の題名・面の記号・穴のある面
ごとの横と縦の止める位置（`face_point` と `chain_from_stops` の結果）を `<case>.parts.json` として書く処理を
足す（`--steps-only` と同じく、今の正解ファイルに足すだけの指定も）。描き方のクレートのテストで全件
突き合わせる。

### 描き方（`crates/nichiyou-daiku-drawing`、新しいクレート。core に依存）

- `text`: DejaVu Sans の字幅の表（使う字: ASCII、×、φ、↧、▲ ほか題名に出るもの）。数字の高さを 2.5mm
  （`TEXT_SIZE`）にしたときの幅と行の高さを返す。
- `chain`: `shell/drawing.py` の寸法線の描き方を移す。段（`dimension_levels`: 線 8、補助線の超え 2、文字との
  間 0.6、斜めの引き出し 2.5、全体まで 4）、補助線（外形から 1 空ける）、矢印（長さ 2）、区間に入る数値は
  中に、入らない数値は lumber でなければ外の列（`spread`）と折れた引き出し線、全体の数値が入らなければ
  低い側の外に線を延ばして書く、入りきらないときは知らせる文。
- `solid`: 1 本の材（箱と穴）を平行投影し、見える線と隠れ線に分ける（決定 7）。投影は CLI と同じ
  （見る向き、上は z、右は 上×見る向き）。
- `part_sheet`: `shell/parts.py` の組み方を移す。幅 280mm、余白 6、斜めの図の枠 70×60、記号の列 22、縮尺は
  0.8 まで、細い面は高さ 22mm まで広げる、面の間 10、▲ の長さ 3.5。斜めの図は記号の付いた面がいちばん
  多く見える向きから描き、記号を右の列に並べて引き出し線でつなぐ（裏の面は破線）、▲ は材の外から基準の
  端を指す。面の図は下から上へ、最初の記号の面が上。
- `svg`: SVG の書き出し。層ごとに線の太さと色（外形 0.35 黒、隠れ線 0.15 灰の破線、細線 0.13）、文字は
  `<text>`、矢印と ▲ は塗りつぶし。単位は mm（`viewBox` はページの mm）。

### WASM（`crates/nichiyou-daiku-wasm`）

`part_drawing(source, part) -> String`（JSON）を足す。`{"svg": "<svg …>", "error": null}`、作れないときは
`{"svg": null, "error": "…何が悪く、どう直すか…"}`。`part` は view の `parts` の番号。穴のない部品は
エラー（「この部品には穴が無いので、図は無い」）。

### web

- 部品表（`stepsPanel`）: 穴のある部品の行に [Drawing]。行を押すと今のとおり 3D で青、[Drawing] を押すと
  部品図。view の `parts` に穴の有無（`drilled`）を足す。
- `drawing.ts`（純粋）: 拡大・移動の計算（`viewBox` を、指の位置を中心に拡大・ドラッグで移動・全体に
  合わせる）。
- 図の欄: 右の 3D の場所に入れ替わる欄。上に [3D] と [Fit]、ホイール・ピンチで拡大、ドラッグで移動。
  作れないときは理由を出す。同じファイルの同じ部品の SVG は覚えておき、作り直さない。
- `main`: [Drawing] で図の欄に、[3D]・手順を送る・Model タブで 3D に戻す。

## テスト

- Rust core: 正解ファイル（671 件で、穴のある部品ごとの題名・面の記号・止める位置）。単体テスト: 面の
  記号（front に付く場合と付かない場合）、斜めの図の向き、`chain_from_stops`、`spread`（Python 版の例）。
- 描き方のクレート: 字幅（数字は同じ幅、長い文字列ほど広い）、寸法線（中・外の列・lumber・全体が入らない
  とき・入りきらない知らせ）、1 本の材の隠れ線（斜めから見た箱で見える辺 9 本・隠れる辺 3 本、表と裏の
  面の穴、貫通穴の出口）、部品図の組み方（題名の折り返し、面の図の大きさ、▲ の位置）。
- WASM: ビルドしたものを Node で読み、例の部品図が SVG で返ること。
- TypeScript: [Drawing] が穴のある部品にだけ付くこと、図と 3D の入れ替え、拡大・移動の計算、作れない
  ときの表示。
- 見た目: Tailscale 経由で PC とスマホから、ファイルワゴンの部品図を CLI の画像と見比べ、ユーザーが
  確かめる。
