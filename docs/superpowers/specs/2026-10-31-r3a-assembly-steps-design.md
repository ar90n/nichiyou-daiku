# R3a 組み立て手順の手順送り（ビューアー） 設計

- 日付: 2026-10-31
- ステータス: 設計（未実装）
- ブランチ: `next`（作業は `next-r3a-steps`）
- 親: `2026-10-29-next-generation-rust-core-design.md`（次世代の R3 組み立てマニュアルの A）、
  `2026-10-31-r2-browser-viewer-design.md`（R2 のビューアー）

## 目的

ビューアーで組み立てマニュアルを見られるようにする（ユーザーの要望、R2 を確かめたあと）。ユーザーは中身を
「全部」と答えた。手順送り・寸法・紙のマニュアルの 3 つで、互いに独立した大きさがあるので、R3 組み立て
マニュアルとして A → B → C の順に分けて作る（ユーザー承認）。

- **A 手順送り（この文書）**: 部品表と、手順を 1 つずつ送って 3D で見る画面。
- **B 寸法**: A の 3D に、新しい部材をどこに付けるかの寸法線を出す（寸法の区切り方を Rust に移す）。
- **C 紙のマニュアル**: 部品表・穴の部品図・手順ごとの図（隠れ線あり）をブラウザで表示し、印刷する（図面の
  描き方を Rust に移す。元の R4 の図面を取り込む）。

B と C は A の手順の計画を使い、C の隠れ線の処理は図面と同じものなので、この順にする。

## 決定と理由

1. **PC と、作業場のスマホ・タブレットの両方で見る**（ユーザー）。PC の画面に加え、狭い画面では 3D と手順の
   カードを縦に並べ、前へ／次へを指で押しやすくする。R2 で外したスマートフォン向けの作り込みのうち、Steps に
   要る分をここで入れる。
2. **3D には、その手順でできた部分だけを描く**（ユーザー、CLI の手順の画像と同じ）。手順が終わったときの
   「つながった塊」（`shown`）だけを描き、前の手順の部材を灰色、この手順の部材を青にする。別に組んだ塊
   （sub-assembly）は join の手順まで出ない。まだ付けていない部材を薄く描く案は選ばなかった。
3. **[Model] [Steps] のタブで切り替える**（ユーザー）。左の欄に手順の欄を足す案は、狭い画面で欄が縦に長く
   なるので選ばなかった。
4. **手順・部品表・ビスの数は Rust の core で計算し、view の JSON に足す**（ユーザー承認）。ビューアー、
   後の CLI の `steps`、B と C で同じ処理を使い、R1 と同じく Python 版の正解ファイルと突き合わせられる。
   TypeScript で計算する案は CLI のために同じ処理を二度書くことになり、別の WASM の関数にする案は呼ぶのが
   二回になるだけなので選ばなかった。
5. **手順の計画は寸法図の向き（`view`）まで一度に移す**。A では使わないが、B と C が使い、`steps.py` を
   丸ごと正解ファイルと突き合わせられる。
6. **`steps` ブロックが無いときは、CLI と同じく 1 部材ずつ手順にし、Steps タブの先頭に案内を出す**。
   案内の文は CLI と同じ（`No steps block: each step adds one piece. Group pieces with a steps block, e.g.
   ``steps { "Frame": a, b, ... }``.`）。
7. **書き間違い（エラー）があれば Steps タブは押せない。問題があるだけなら手順を出し、件数を一行で知らせる**。
   問題のある設計でも、配置できた範囲で手順は読める。手順が誤っているかもしれないことは知らせる。
8. **手順を変えても、カメラは見ている向きのまま、その手順の部分に合わせて寄る**。手順ごとに向きが変わると、
   どこが変わったかを追いにくい。
9. **穴は、描いた部材の穴をすべて描く**。部材は組み立ての前に穴をあけておく（部品図はその前提）。
10. **URL に手順を残す**（`&step=N`、`step=0` は部品表）。リンクでその手順をそのまま開ける。

## 組み立て

### core（`crates/nichiyou-daiku-core`）

- `steps.rs`: `core/assembly/steps.py` の `plan_steps` を移す。`StepPlan { declared, steps }`、手順ごとに
  `number`・`name`（`steps` ブロックが無ければ None）・`pieces`・`connections`（その手順でつなぐ接続）・
  `kind`（`first`・`attach`・`sub-assembly`・`join`）・`shown`（その手順が残す塊の部材、モデルの順）・
  `view`（寸法図が見る軸と側）。`grouping_hint` も移す。
- `parts.rs`: `core/assembly/parts.py` の `part_groups` を移す。材種と長さが同じで、板をそれ自身に重ねる回転
  （2x2 は長さの軸の 1/4 回転も）で穴が重なる部材を、宣言の順にまとめる。鏡に映した形の部材は別の部品。
  貫通穴はどちらの面からでも同じ穴とみなす。比べる許しは 0.05mm。
- `hardware.rs`: `shell/resources.py` の `count_hardware` を移す。ダボ、Slim、Coarse、種類なしのビスの順に、
  径と長さ（0.1mm に丸めて）ごとに数える。接続を渡すとその接続の分だけ数える。名前は CLI と同じ
  （`Dowel 8x30`、`Slim screw 3.8x65`）。後の CLI のレポートの買い物リストでも使う。
- `view` の JSON に足す（エラーのときは `parts`・`steps` は空、`steps_declared` は false、`steps_hint` は null）:

  ```json
  {
    "parts": [{"pieces": ["leg_fl", "leg_fr"], "type": "2x4", "length": 750.0, "count": 2}],
    "steps": [
      {"number": 2, "name": "Right frame", "kind": "sub-assembly",
       "pieces": ["leg_fr", "apron_r"], "connections": [["apron_r", "leg_fr"]],
       "shown": ["leg_fr", "apron_r"], "view": {"axis": "x", "side": -1},
       "hardware": [{"name": "Slim screw 3.8x65", "count": 4}]}
    ],
    "steps_declared": true,
    "steps_hint": null
  }
  ```

  `hardware` はその手順の接続の留め具。WASM の関数は増えない（`view` のまま）。

### 正解ファイル

`tools/make_goldens.py` に、組み立てられる場合に Python 版の手順・部品表・手順ごとのビスの数・案内を
`<case>.steps.json` として書く処理を足す。今の正解ファイルでは 671 件。Rust のテストで view の `parts`・
`steps`・`steps_declared`・`steps_hint` と突き合わせる。

### web

- `steps.ts`（WebGL に触れない）: 手順から、描く部材・灰色の部材・青の部材・カメラを合わせる範囲を決める。
  部品表の行から、色を付ける部材を決める。URL の `step=` を読み、範囲の外の番号はいちばん近い手順にする。
- パネル: Steps タブの左の欄（お知らせ、部品表、手順のカード、前へ／次へ）。
- `viewer`: 一部の部材だけを描く、灰色と青を塗る、向きを保ったまま範囲に合わせて寄る、を足す。
- `main`: タブの切り替え、← → のキー、URL の `step=` の読み書き。

## 画面と動き

```
PC（Steps タブ）
[Open][URL____][Open URL] wagon.nd 440×530×750mm ⚠0  [Model][Steps]
┌───────────────────────────┬──────────────────────────────┐
│ (No steps block: …)        │ [Front][Top][Right][Iso] [Labels]
│ Parts                      │                              │
│  leg_fl, leg_fr … 2x4 750 ×4│        3D                    │
│ Step 1 - Frame             │  前の手順 = 灰色              │
│▶Step 2 - Right (sub-assembly)│  この手順 = 青              │
│   leg_fr  2x4  750         │  まだの部材・別の塊 = 描かない │
│   Slim screw 3.8x65 ×4     │                              │
│ Step 3 …                   │                              │
│ [◀ Prev]   2 / 5   [Next ▶]│                              │
└───────────────────────────┴──────────────────────────────┘
```

- タブ: ヘッダーの右に [Model] [Steps]。Model は R2 のまま。書き間違いがあるときは Steps を押せない
  （押せない理由を添える）。
- Steps タブの左の欄:
  - 先頭のお知らせ: `steps` ブロックが無いときの案内。問題があるときは
    `This design has N problems (see Model); the steps may be wrong`。
  - Parts（手順 0）: 部品表（部材・材種・長さ・数）。3D は完成形で、行を押すとその部材を青にする。
  - 手順のカード: 見出しは CLI と同じ（`Step 2 - Right frame (sub-assembly)`、join は `(join)`、名前が無ければ
    `Step 2`）。いまの手順だけ開き、足す部材（材種・長さ）と留め具の数を出す。カードを押すとその手順へ。
  - 送る: 下の [◀ Prev] [Next ▶] と、キーボードの ← →。端では押せない。
- 3D: その手順の `shown` だけを描き、前の手順の部材を灰色、この手順の部材を青にする。描いた部材の穴と
  ラベルも出す。手順を変えると、見ている向きのまま `shown` の範囲に合わせて寄る。視点のボタンはそのまま
  使える。Steps タブでは部材を押しても何もしない。
- 狭い画面（幅 760px 未満）: Steps は 3D を上に、手順のカードを下にし、前へ／次へを指で押しやすい大きさ
  （高さ 44px 以上）にする。本文の欄は出さない。Model も縦に積む（3D、問題、部材、本文）。
- URL: `?src=…&step=N` で、その手順を開いた Steps タブになる。手順を送るたびにアドレスバーを書き換える。
  Model に戻ると `step` を消す。

## テスト

- Rust:
  - 正解ファイル: 組み立てられるすべての件で、`parts`・`steps`・`steps_declared`・`steps_hint` が Python 版と
    一致すること。食い違いを残すなら、R1 と同じく理由を書いて一覧（`known_differences.toml`）に載せる。
  - 単体テスト: 手順の種類（first・attach・sub-assembly・join）、`steps` ブロックが無いときの順番、部品の
    まとめ方（回して同じ穴ならまとめる、鏡に映した形は別、2x2 の 1/4 回転、貫通穴）、留め具の名前と並び。
- TypeScript（vitest、jsdom）: 手順ごとの描く部材・灰色・青とカメラの範囲、部品表の行の色、URL の `step=`
  の読み書きと範囲の外の番号、カードの見出しと開閉、お知らせ、書き間違いのときに押せない Steps タブ、
  一部の部材だけを描くことと向きを保って寄ること（R2 の、描いた部材を数える偽のレンダラーで）。
- 見た目: Tailscale 経由で PC とスマホから、ファイルワゴン（`steps` ブロックあり）と `steps` ブロックの無い
  例を開き、ユーザーが確かめる。

## A で作らないもの

寸法（B）、紙のマニュアル・部品図・印刷（C）、ビューアーで手順を編集すること、部材が動いて付く
アニメーション、CLI の `steps`（R4）。

## A が終わる条件

- 上のテストがすべて通り、`make check` と `make ci-local` が通る。
- WASM の大きさを測り直してこの文書に書いてある。
- ユーザーが PC とスマホで確かめた。
