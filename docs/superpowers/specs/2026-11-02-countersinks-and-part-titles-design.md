# 皿取りと部品図の題名 設計

- 日付: 2026-11-02
- ステータス: 設計（未実装）
- ブランチ: `next`（作業は `next-countersinks`）
- 親: `2026-11-01-r4a-cli-text-design.md`（決定 6）、`2026-11-01-r3c1-part-drawings-design.md`（部品図）

## 目的

ユーザーの 2 つの要望を入れる（2026-11-01）。

- ねじ穴は皿の部分を削る（皿取り: 皿ねじの頭が面にそろうよう、穴の口を円すい形に削る）。
- 部品図の題名（`leg_fl, leg_fr, leg_bl, leg_br ×4 2x4 750 φ2.5 ×12 φ10 ↧51 ×6`）は中身はよいが、見せ方を読みやすくする。

皿取りは下穴のデータ・部品図・3D・report を Python 版から変えるので、R4a で移し替えを確かめ終えてから Rust にだけ入れる。

## 決定と理由

1. **皿取りは、頭がターゲットの外側の面に乗るねじすべてに付ける**。座掘りをするねじ（幅の狭い面を通すもの）は頭が座掘りの底に沈むので付けない。ダボにも付けない。
2. **皿の口の径はねじ径の 2 倍を 0.5mm 刻みにしたもの、角度は 90°**（ユーザー）。頭の径はおよそねじ径の 2 倍なので、3.3→6.5、3.8→7.5、4.2→8.5、4.5→9、5.2→10.5mm。深さは (口の径 − 下穴の径) ÷ 2。ねじの種類ごとに頭の径の表を持つ案は、表の値をどの製品に合わせるかを決める必要があるので選ばなかった。.nd で指定できるようにする案は、文法とエラーの文が増えるので選ばなかった。
3. **そのねじのターゲットの下穴（貫通）は、頭の側の面の穴として記録し、皿の口の径を持たせる**（ユーザー承認）。部品図では頭の側の面に記号と位置の寸法が付き、その面から皿取錐で下穴と皿を一度に開ける実際の手順と同じになる。貫通穴なので穴の位置と形（3D・ぶつかりの判定）は変わらない。皿取りを座掘りと同じく別の穴として足す案は、同じ穴に記号の付いた面が 2 つでき、どちらから開けるかが分かりにくいので選ばなかった。貫通穴に「反対の端に皿取り」の印を付ける案は、その決まりがどこでも分かりにくいので選ばなかった。
4. **ねじの位置・穴どうしのぶつかりの判定・`validate` は変えない**。`Fastener` の当たる面の点はそのまま。ぶつかりは下穴の径の円柱で判定し、皿の浅い円すいは見ない。
5. **部品図の題名は「属性: 値」の形にする**（ユーザー）。左に属性の名前（太字）、右に値を縦に並べ、値の始まりをそろえる。罫線は付けない。表（罫線つき）の案は、ユーザーが「属性: 値」の形を選んだので選ばなかった。
6. **正解ファイルは、Python とのつながりをできるだけ残す**。穴（`holes.json`）と部品図の事実（`parts.json`）は、Rust の穴を Python の形（当たる面に記録、皿取りなし）に戻して Python の正解と比べる。変わったのが記録の面と皿取りだけであることを、全件で機械的に確かめられる。report は下穴の節と Drill Bits が変わるので、Rust の出力を正解として書き直す（その前に、元の Python の正解との違いがその 2 か所だけであることを全件で確かめる）。

7. **鏡に映した形の部品の対は、部品図の題名に `Mirror of:` で相手の部材名を書く**（ユーザー、2026-11-02）。皿取りの面が決まると鏡像の対が別の部品になり（ワゴンの脚は 4 本 1 部品から 2 本ずつ 2 部品になった）、図がほとんど同じで取り違えやすい。鏡像は、穴を幅の方向に映したものが、材を回して相手の穴と重なることで見分ける（映しと回しで、どの面に映しても表せる）。部品の番号でなく部材名で書くのは、マニュアルでも後の CLI の部品図でも同じ文で読めるようにするため。属性の名前の太字は幅を見積もるしかないので、左端に合わせて書く。

## 皿取り

- core の `Hole` に `countersink: Option<f64>`（口の径）を足す。ほかの穴はすべて None。
- `Assembly::of` で穴を並べるとき、座掘りの無いねじについて、ターゲットの下穴を頭の側の面（当たる面の反対）の点に記録し、`countersink` を付ける。座掘りのあるねじ・ダボ・ベースの穴は今のまま。
- DSL 仕様書のねじの「Rules」の穴の行に、座掘りの無いねじは頭の側から下穴を開け、ねじ径の 2 倍（0.5mm 刻み）・90° の皿取りをすることを足す。

## 出るところ

- **ビューアーの 3D**: 穴の JSON に `countersink`（口の径か null）。皿取りのある穴は、下穴の円柱に加えて、口に円すい（面の側が口の径、奥が下穴の径、高さは皿の深さ）を描く。
- **部品図（C1）**: 皿取りのある穴の口に、口の径の円をもう 1 つ描く（同心円）。面の図でも斜めの図でも、見え方は口の円と同じ（面が表なら実線、裏なら隠れ線）。
- **部品図の題名**: 今の題名の場所に、次の形で並べる。

  ```
  Pieces:  leg_fl, leg_fr, leg_bl, leg_br
  Count:   4
  Lumber:  2x4
  Length:  750mm
  Holes:   φ2.5 through, countersunk φ7.5   ×12
           φ10, 51mm deep                   ×6
  ```

  - 属性の名前は太字、値は同じ位置から始める。
  - Holes は穴の種類ごとに 1 行。`φ径` に ` through` か `, 深さmm deep`、皿取りがあれば `, countersunk φ口の径`。右端に 1 本あたりの数をそろえて書く。行の順は今と同じく径の順、同じ径なら止め穴が先、同じ径と深さなら皿取りの無いものが先。
  - 部材名が長いときは値の列の中で折り返す（2 行目も値の位置から）。
  - core は題名を、1 行の文字列（今の `part_title`）ではなく組み立て済みのデータ（部材名・本数・材種・長さ・穴の種類ごとの行）で返し、描き方のクレートが並べる。
- **手順の図（C2）とマニュアル（C3）**: 同じ描き方なので、そのまま皿取りの円が出る。
- **report（R4a）**: 下穴の表に `Countersink` の列（`φ7.5mm`、無ければ `-`）。Drill Bits に口の径ごとの行（`- **Countersink φ7.5mm**: 48 holes`）。

## テスト

- 正解ファイル（決定 6）:
  - `holes.json`: Rust の穴のうち皿取りのあるものを、反対の面（当たる面）の点に記録し直して皿取りを外し、Python の正解と比べる（今の比べ方のまま）。
  - `parts.json`: 同じく穴を Python の形に戻して面の記号・止める位置を計算し、Python の正解と比べる。題名は、組み立て済みのデータを今までの 1 行の形に書き直すテスト用の関数で比べる。
  - report（`cli-report.txt` と report のオプションの例）: Rust の出力を正解として書き直す（`ND_BLESS=1` で書き出す）。書き直す前に、元の Python の正解との違いが Pilot Holes の節と Drill Bits の行だけであることを全件で確かめる。`tools/make_goldens.py --cli` は report の正解を書かない（`validate` の分は今のまま Python から作る）。
- 単体テスト:
  - core: 皿の口の径（3.3→6.5、3.8→7.5、4.2→8.5、4.5→9、5.2→10.5）。幅の広い面を通すねじは頭の側に皿取りつきで記録されること。座掘りのねじ・ダボには付かないこと。頭の側の面に記号が付くこと。
  - 部品図: 皿取りの同心円が描かれること。「属性: 値」の並び（値の始まりがそろう、Holes が種類ごとに 1 行、長い部材名の折り返し）。
  - ビューアー: 皿取りのある穴に円すいが付くこと。
- 見た目: ファイルワゴンの部品図・手順の図・3D をユーザーが見て確かめる（題名と皿取りの円、3D の円すい）。

## 作らないもの

皿取りの大きさを .nd で指定すること、ねじの種類ごとの頭の径の表、皿の重なりの判定、R4b（`render`・`steps`・`drawing`・`view`）。
