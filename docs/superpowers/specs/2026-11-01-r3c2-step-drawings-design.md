- 日付: 2026-11-01
- ステータス: 設計（未実装）
- ブランチ: `next`（作業は `next-r3c2-step-drawings`）
- 親: `2026-10-29-next-generation-rust-core-design.md`（R3 組み立てマニュアルの C2）、

## 目的

ビューアーの手順送りから、CLI の `steps` が書く `step-NN.png` と同じ手順の図を開けるようにする。C1 の描き方の
土台に、箱どうしが隠し合う隠れ線を足す。この隠れ線は後の CLI（`steps`・`drawing`・`render`）でも使う。

## 決定と理由

1. **開いた手順のカードに [Drawing] を付け、押すと 3D の場所がその手順の図になる**（ユーザー）。部品図
   （C1）と同じ欄と操作。図を C3 のマニュアルだけで見せる案は、手順送りの途中で図を確かめられないので選ば
   なかった。
2. **図を開いたまま手順を送ると、その手順の図に切り替わる**（ユーザー）。部品表（手順 0）まで戻ったら 3D に
   戻す。部品図を開いているときは C1 のとおり送ると閉じる。
3. **中身は CLI の手順の図と同じ**。見出し、左に斜めの図（前の手順の部材は灰、今回の部材は黒、今回の部材名を
   白い地の上に、左下に寸法図の向きを示す灰色の矢印）、右に寸法図（R3b と同じ寸法、今回の部材名、今回の
   部材の隠れ線を破線、向きが分からないときは灰色の参照名）。CLI で決めた見せ方（M4-4、2026-10-17 の向きの
   手がかり）をそのまま使う。
4. **隠れ線は、世界の軸にそろった箱どうしとして正確に求める**。部材はどれも回転が 90° 刻みの箱なので、
   世界の座標では軸にそろった箱になる。線（箱の辺、穴の円の多角形の辺、穴の底と側面）ごとに、その上の点から
   見る側への光線がほかの箱の中を通る範囲を、線の上の割合の区間で求め、見える部分と隠れる部分に分ける。
   自分の箱が隠すかどうかは C1 と同じく面の向きで決める。線を細かく切って点ごとに調べる案は、区間の端が
   ぼやけ、線が増えるので選ばなかった。一般の隠れ線の処理（OCP のような）は要らない。
5. **ほかの箱は 0.000001mm だけ内側に縮めて判定する**。接している部材どうし（面が同じ平面）で、境目の辺が
   隠れないようにする。CLI の部材名の判定（`views.py: _blocks`）と同じ余裕。
6. **数値は R3b の突き合わせで足り、線は Python 版と比べない**。寸法の区切りは R3b で 671 件を突き合わせ
   済み。隠れ線は場面を決めた単体テストで押さえ、最後に CLI の図と見比べる。
7. **入りきらない数値の知らせは C1 と同じく図の上に出す**。助言は CLI と同じ（部材が 1 本の手順は「レポートの
   Anchor Details を見る」、複数は「手順を分ける」）。
8. **C1 の `PartDrawing` を `Drawing`（SVG と知らせ）という名前にし、部品図と手順の図で同じ形を返す**。

## 組み立て

### 描き方のクレート（`crates/nichiyou-daiku-drawing`）

- `views`: CLI の 2 種類の見る向き。斜めの図（−x +y +z から、上は z）と、手順の寸法図（軸と向きから、上は z、
  z の向きから見るときは −y）。`solid::Projection` に上の向きを指定できる作り方を足す（中心は世界の原点）。
- `hidden`: 箱どうしの隠れ線（決定 4・5）。
  - 部材ごとの線: 箱の 12 本の辺、穴の入口の円（多角形）、底の円、側面の輪郭 2 本（C1 の `board_lines` と
    同じ線を、世界の座標で）。
  - 自分の箱: 辺は接する 2 面のどちらかが表なら見える、穴の入口は面が表なら見える、底と側面は隠れる、
    貫通穴の出口は反対の面が表なら見える（C1 と同じ）。
  - ほかの箱: 線の各区間について、`点 + t × 見る向き`（t > 0）が縮めた箱の中を通る区間を、線の割合
    `s ∈ [0, 1]` の区間として求める（s と t の 2 変数の不等式を満たす多角形を切り出し、その s の範囲）。区間を
    合わせ、残りを見える部分にする。
  - 返すもの: 部材ごとの見える線と隠れる線（2 次元に投影したもの）。
- `labels`: 部材名の置き場所（`views.py: label_at`）。中心、隠れていれば一番長い辺に沿って 1/4・3/4・1/8・
  7/8 の点を順に、`shown` のほかの部材が光線をさえぎらない最初の点。無ければ無し。
- `step_sheet`: 手順の図の組み方（`shell/instructions.py: step_image` を移す）。ページ 280×140、余白 6、
  見出しの帯 10。斜めの図は左半分に 0.9 の割合で収め、矢印（中心 (28, 22)、長さ 30、幅 5、先の長さ 10、
  先の幅 12）の 6mm 以内に線が入れば 0.95 倍ずつ縮める（0.3 まで）。寸法図は右半分に、左と下に寸法の帯を
  空けて収め、`step_dimensions` の 2 本を C1 の `draw_chain` で描く。部材名は数値・寸法線・矢印・ほかの名前と
  重ならないところだけに置き、白い地を敷く。参照名（`_references`）: 今回の部材名だけでは寸法図の左右（上から
  なら上下も）が分からないとき、前の手順の部材を、今回の接続の相手から、近い順に、両方の図に置ける・自分の
  部材の上に乗るものを足していき、10mm 以上離れた名前が 2 つそろったら止める。そろわなければ足さない。
  線の層: 前の部材 灰（#a0a0a0）0.18、今回の部材 黒 0.5、今回の部材の隠れ線（寸法図だけ）破線 0.25、
  寸法線 0.13、名前の地 白、文字 黒、矢印と参照名 灰（#969696）。外枠は灰の細線。
- `lib.rs`: `Drawing { svg, notes }`（C1 の `PartDrawing` の名前を変える）、`step_drawing(source, step)`。

### WASM

`step_drawing(source, step) -> String`（JSON）。`{svg, notes, error}`、`step` は手順の番号（1 から）。範囲外は
「手順 N は無い（手順は 1〜M）」の形のエラー。

### web

- 手順のカード（`stepsPanel`）: 開いた手順のカードの表の下に [Drawing]（`onStepDrawing(step)`）。
- `main`: 手順の図は手順の番号ごとに覚える。図の欄が手順の図を出しているときに手順を送ったら、その手順の
  図にする（手順 0 なら閉じる）。部品図のときは閉じる。この決め方は純粋な関数にして試す。

## テスト

- 隠れ線: 前後の 2 つの箱で奥の箱の辺の隠れる区間（割合まで）、接している 2 つの箱の境目の辺が見えること、
  手前の箱に隠れた穴の円、自分の裏の辺。
- 部材名: 中心が隠れたら長い辺に沿った点、どこも隠れたら無し。
- 手順の図: 見出し、前の部材と今回の部材の層、今回の部材の隠れ線は寸法図だけ、矢印の向き、知らせの助言
  （1 本と複数）。
- WASM: Rust と Node で例の手順の図が SVG で返ること、範囲外の手順のエラー。
- TypeScript: [Drawing] が開いた手順のカードに出ること、図を開いたまま手順を送ったときの切り替え。
- 見た目: ファイルワゴンの 6 手順を書き出して CLI の `step-NN.png` と見比べる。ユーザーが PC とスマホで
  確かめる。

## C2 で作らないもの

マニュアル全体の組み方と印刷（C3）、CLI の `steps`（R4）、図面（`drawing`）の 4 方向の図と `render` の確認用
の図（R4。この隠れ線を使える）。

## C2 が終わる条件

- 上のテストがすべて通り、`make check` と `make ci-local` が通る。
- WASM の大きさを測り直してこの文書に書いてある。
- ユーザーが PC とスマホで、CLI の手順の図と見比べて確かめた。

WASM は R3c2 で 0.85 MB（851,830 バイト）、gzip で 0.20 MB（204,304 バイト）。R3c1 の 0.75 MB／0.19 MB から、箱どうしの隠れ線・部材名の置き場所・手順の図の組み方の分が増えた（2026-11-01）。
