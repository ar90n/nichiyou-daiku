# 未知数と部分拘束（Unknown Lengths and Sliding Connections）設計

- 日付: 2026-10-12
- ステータス: 実装済み（ブランチ feat/unknowns）
- 実装との差分: 検証用の形状として `shape_for_checks`（未知の長さを無限大とみなす）を足した。`shell/resources.py` は解いた後の値（`shape.length`、`as_edge_point(anchor).offset`）を読む。例 `examples/nd_files/simple_table_unknowns.nd` を足した。レビュー後: 解いた後のモデルを作り直すときの検証エラー（オフセットが解いた長さを超える等）も `ResolutionError`（接続付き）にした。`placement.py` の共有部分は公開名にした（`solve_positions`、`PositionSolution`、`edge_axis`、`face_normal`、`axis_index`、`round_mm`）。
- 対象: M2-4（拡張）の残り 2 項目「長さやオフセットを未知数にする」「一部の自由度だけを拘束する接続」
- 決め方: ユーザーの `/goal`（M2 系の開発を完了させる）により、確認を挟まずに決めた。判断と理由をここに残す。

## 背景

- 部材の長さは手で計算して書く必要がある（幕板 = 全体の幅 − 脚の幅 × 2 など）。計算を誤ると配置が矛盾する。
- 接続はいつも 3 軸すべての位置を決める。天板を 2 本目の幕板にも留めたいとき、2 本目の接続にも正確なオフセットを書く必要があり、
  少しでもずれると矛盾になる。

## 目的

- 長さを「接続から決まる未知数」として書けるようにする。
- 辺に沿った位置（オフセット）を未知数にした接続、つまり「接して面は揃うが、辺に沿っては自由に滑る」接続を書けるようにする。
  これが「一部の自由度だけを拘束する接続」にあたる。
- どちらも M2-1 の方針（全接続を同時に厳密に解く、先に宣言した接続を優先、矛盾した拘束だけを報告）を保つ。

## 決定事項と理由

1. **未知数は 2 種類: 部材の長さと、アンカーのオフセット。** オフセットの未知数が部分拘束になる（その接続は辺の方向の位置を決めない）。
   回転を自由にする接続などほかの部分拘束は入れない（90° 刻みで厳密という方針と合わず、今の用途もない）。
2. **書き方:** DSL は長さ `=?`、オフセット `?`（例 `RF? BT?`）。Python API は `Piece.of(type, None, id)` と `Anchor.of(contact, edge, None)`。
   JSON 記法では使えない（簡略表記が推奨で、JSON は補助のため）。
3. **オフセットの `?` は接続の両方のアンカーに付ける。** 片方だけでは意味が曖昧になる（どちらにしても滑る）ので、検証でエラーにする。
4. **未知数を解いて「すべてが数値のモデル」を作る（`resolve_model`）。** `parse_dsl` と `Assembly.of` が自動で行う。
   これ以降（配置・留め具・レポート・3D・図面）は今のまま数値のモデルだけを扱うので、変更が要らない。
5. **解き方:** M2-1 の軸ごとの差分制約（重み付き Union-Find）を広げる。部材の長さ方向の軸では、部材に「下端」と「上端」の
   2 つの点を持たせる。長さが分かっている部材は 2 点の差を長さに固定し、未知の部材は固定しない。アンカーの点は、
   長さ方向では下端または上端からの距離で表す（`FromMax` の辺上の点や top 面の点は上端から）。オフセットが未知の接続は、
   辺の方向の制約を加えない。今のモデル（未知数なし）の結果は変わらない。
6. **決まらない・おかしい場合はエラー（`ResolutionError`、`ValueError` の一種）。** 数値のモデルが作れないので、警告して続行はしない。
   - 長さが接続で決まらない / 0 以下になる
   - 部材の位置がどこかの軸で決まらない（滑る接続だけでつながっている）
   - 滑る接続の 2 つの辺が、辺の方向で重ならない（接していない）
   DSL ではその部材または接続の行と列を付けた `DSLValidationError` になる。
7. **矛盾は今までどおり先に宣言した接続を優先する。** 未知数を解くときに矛盾として捨てた接続は、数値のモデルで
   配置を解き直したときにも矛盾として報告される。その接続のオフセットが未知なら、回転の矛盾では 0 を、
   それ以外の矛盾ではほかの接続で決まった位置から求めた値（辺が重ならなければ範囲内に詰めた値）を入れる。
   0 を入れると、ユーザーが自由にした方向にも偽の矛盾が出るため（レビューで判明）。
8. **滑る接続の具体的なオフセット:** 2 つの辺が重なる区間のうち、ベースのオフセットが最も小さくなる点を選ぶ。
   両方の点がその区間に入るので、どちらのオフセットも辺の長さの範囲に収まる。

## スコープ外

- 未知数を変数や式から参照すること（解いた長さを `W` のように使う）
- 未知数の最適化（最小二乗など。M2-1 で「誤差を広げない」と決めている）
- JSON 記法での未知数

## 設計

### データモデル

- `Piece.length: PieceLength | None`（`None` は未知）。`get_shape(piece)` は未知の長さで呼ぶと `ValueError`。
- `Anchor.offset: Offset | None`（`None` は未知）。
- 検証は、未知の値を使う検査だけを飛ばす（`BoundAnchor` のオフセット範囲、ダボ・ビスの深さと径）。解いたモデルを
  作り直すときに、すべての検査がもう一度走る。
- `Connection` の検証に「オフセットの未知は両方のアンカーか、どちらでもないか」を足す。

### 解く処理（`core/placement.py`）

- 回転（Step 1）は今のまま。
- 位置（Step 2）の Union-Find のノードを `(piece_id, "down" | "top")` にする。部材の長さ方向に当たるワールド軸では両方、
  それ以外の軸では `"down"` だけを使う。長さが分かっている部材は、接続より先に `top - down = ±長さ` を加える。
- アンカーの点は、長さ 0 の箱で計算した局所座標と「下端・上端のどちらから測るか」で表す
  （top 面を含む、または長さ方向の辺で `FromMax` なら上端）。
- 矛盾の `loop` は今までどおり部材 ID の経路で表す。
- `solve_placement` は数値のモデルだけを受け付ける（未知数があれば `ValueError`）。

### 未知数の解決（`core/resolve.py`、新規）

`resolve_model(model) -> Model`: 未知数がなければそのまま返す。あれば上の位置の解き方で解き、

1. 未知の長さ = `±(top − down)`。同じ成分にない、または 0 以下なら `ResolutionError`。
2. 各部材の位置が、その部材のグループの先頭の部材と全軸で同じ成分にあることを確かめる（滑る接続だけでは決まらない）。
3. 採用された滑る接続ごとに、2 つの辺のワールドでの区間の重なりから具体的なオフセット（`FromMin`）を求める。
4. 部材と接続を数値で作り直した `Model` を返す。

`ResolutionError` は `piece_id` または `(base_id, target_id)` を持つ。

### DSL

- `compact_length: "=" (sum | "?")`、`compact_offset: ... | "?"`。
- 変換の最後に `resolve_model` を呼び、`ResolutionError` を該当する部材・接続の行と列に結び付ける。

## テスト

- 長さ: `simple_table_compact.nd` の前幕板を `=?` にすると 622 に解ける。
  前後の幕板を両方 `=?` にすると脚の間隔が決まらずエラー（前幕板の行）。0 以下になる長さもエラー。
- 滑る接続: 天板を後ろの幕板にも `?` で留めた設計が、矛盾なく解け、留め具が両方の接続に置かれ、元の設計と配置が同じ。
  滑る接続だけでつながった部材はエラー。辺が重ならない滑る接続はエラー。`?` が片方だけの接続はエラー。
- Python API: `Assembly.of` が未知数のあるモデルを解く。`solve_placement` は未知数のあるモデルを拒む。
- 回帰: 既存のテスト（配置の固定値、性質テスト、例の設計）がすべて通る。
